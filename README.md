# Phasma

Phasma is a paranormal investigation station built on an RTL-SDR receiver. It measures the radio spectrum directly and records what it measures: an RF field meter, a spirit box that sweeps real broadcast radio, and a timestamped session log that keeps every reading and every recording for review afterward.

The name is the Greek phasma: an apparition, and in modern Greek the everyday word for spectrum. The instrument reads the spectrum. What it is watching for is the other meaning.

Phasma is a separate program from Eidolon. Eidolon is the pocket kit built for the Flipper Zero; Phasma is the base station, running on a computer with the receiver attached. They share no code and neither one depends on the other.

## Instruments

The field meter reads real RF power anywhere the receiver can tune, HF through 1.7 GHz with an RTL-SDR Blog V4, against a baseline taken in the room, with the peak held and every excursion written to the log.

The spirit box sweeps the FM and AM broadcast bands the way an SB7 does, except the audio is genuine: real demodulated radio, real static, and real fragments of voice and music as the sweep crosses stations. Nothing is synthesized. Each session is recorded to disk as audio, so anything heard in the moment can be played back and checked afterward.

The session log is the spine of the program. Every instrument event is timestamped and written down as it happens, and the audio recordings are filed with the session they belong to.

A word and radar layer is driven by the measured spectrum, and the program labels it for what it is: theater fed by real measurements, not a measurement itself.

## Hardware and honesty

Phasma needs an RTL-SDR Blog V4 (the design targets the RTL2832U family) and a computer to run it. Nothing else is required. The proximity and infrared instruments of the pocket kit are not part of Phasma, because a receiver has no analog input and no infrared eye, and Phasma does not pretend otherwise.

Every number Phasma shows comes from the receiver. Where a display is theater rather than measurement, the program says so on its face.

## Running it

Phasma is a single Python file, `phasma.py`, standard library only, driving the rtl-sdr command line tools (`rtl_power` and `rtl_fm`, found on PATH or in `~/.local/bin`). It is offline-first: no network, no accounts, no telemetry. It was built and verified on a ThinkPad X200 running Trisquel, as an ordinary user, no root.

```
python3 phasma.py doctor
python3 phasma.py field
python3 phasma.py spirit
python3 phasma.py spirit --band airband --seconds 120
```

`doctor` reports whether the receiver tools are present and whether the tuner is already in use. `field` runs the field meter over the FM band by default; `--low`, `--high` and `--bin` set the range and bin width in Hz, `--threshold` the excursion threshold in dB over baseline, `--interval` and `--seconds` the sweep rhythm. `spirit` sweeps FM in 200 kHz steps with a `--dwell` in milliseconds (100 to 500 ms is the SB7 class, 250 by default), playing the audio live through `aplay` and recording it; `--no-play` records silently. The airband mode uses one rtl_fm scan-mode process over 118-137 MHz AM, so its dwell is signal-driven - it lingers where a carrier holds it, the way a scanner does - and `--squelch` is in rtl_fm's own units.

The FM sweep is built from short per-step rtl_fm hops, because rtl_fm has no timed retune of its own. The gaps between steps are the price of that, and they land where an SB7's muting gaps land; the audio inside each step is the receiver's genuine demodulated output.

The tuner is shared hardware. If another program is using the receiver - Passband, readsb, any rtl_* tool - Phasma detects the holder from the process table before it starts, reports it, and exits with code 3. It never opens a busy tuner and never kills another program to get it.

For work while the tuner is busy, both instruments have a simulate mode that runs the full pipeline over a recorded file instead of the receiver: `field --simulate sweep.csv` reads an rtl_power CSV, and `spirit --simulate box.wav` cuts a WAV into dwell windows and measures each one. Simulate mode never opens the receiver either.

## Sessions

Each run opens a session folder under `~/.local/share/phasma/sessions/` (override with `--home` or the PHASMA_HOME environment variable), named by start time and command. A session holds `session.log` with one timestamped line per event as it happens, the raw `field.csv` from rtl_power for field sessions, and the `spirit.wav` sweep recording for spirit sessions. Word cues are logged with the measured level that triggered them and are marked as theater in the log line itself.

## Tests

`python3 -m unittest discover -s tests` runs the unit tests: the rtl_power parser, baseline and excursion detection, the word layer's firing rule, the tuner-holder detection, and both simulate pipelines end to end. All fixtures are generated by the tests; nothing binary is committed.

## State

First release, version 0.1.0. Verified on the X200 with the tuner busy (a Passband airband run held it throughout, untouched): the unit tests pass there, `doctor` finds the tools and names the tuner holder correctly, both simulate pipelines produce complete sessions with the designed excursions and word cues, and both live commands refuse a busy tuner cleanly with exit code 3. A live-tuner sweep - field readings against a known station and a recorded FM sweep with audible station fragments - is the remaining verification, and it waits on the tuner being free rather than on any change to the program.
